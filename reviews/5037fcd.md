## Findings

### 1. Binding another setup while *Play Anim* runs: the old animation keeps moving a slider of the new setup (medium, CONFIRMED)
- **Where:** `set_sim_config!` → `_reset_open_view!` (`src/MakiePlotting.jl`); the animation timer in `UILogic.jl` (~2524).
- **What:**
  - `_reset_open_view!` resets the menus and slider ranges, but it doesn't stop the timer.
  - The timer captured the old `target_widget` and its range. It keeps calling `set_close_to!` on the slot slider `param_1`, which now belongs to `r`.
  - `r` stays pinned at its largest value, and the user can't move it until *Stop Anim*. The animation menu shows `t`, but `t` doesn't move.
  - This is finding 1 of fb11adf reappearing on the bind path. The CHANGELOG says binding "resets the view the same way", and the docstring says "`set_sim_config!` does the same in an open window".
- **Evidence:** `p14_play.log` (GLMakie): `animating=true button=Stop Anim anim menu=t … sliders=[(:r, 0.3), (:y, 0.0), (:t, 0.0)]` for 1.5 s. `p14_noplay.log`: `(:r, 0.1)`. Same result headless (`p11.log` case 6).
- **Fix:** In `_reset_open_view!` (or in `set_sim_config!` when the setup changes), stop the animation the way `reset_plotter!` does: close `manager.animation_timer[]`, set it to `nothing`, and set `is_animating[] = false`.
- **Test:** In plots-1, start *Play Anim* over a swept parameter, then `set_sim_config!(test_heat_2d()); force_simulation(); sleep(0.5)`. Assert `!manager.is_animating[]` and `r == first(heat.varied[:r])`.

### 2. Binding another setup keeps the comparison and a locked camera of the old one (low, CONFIRMED)
- **Where:** `_reset_open_view!` resets only x/y/z/u, `anim_target`, `component` and the sliders.
- **What:**
  - `_reset_config_view!` clears `compare_state`, `layout_cache[:compare_target]` and `camera_cache`. The open window's compare menu and `camera_locked[]` are untouched, so the layout watcher puts the comparison back from the widget.
  - Comparisons that exist in both setups (`time`, `methods`, `component`) and a locked camera survive the bind.
  - `launch_plotter` resets them. The docstring lists "comparison, camera" as part of the default view that `set_sim_config!` "does the same" for.
- **Evidence:**
  - `p16.log`: `heat bound + run  compare state=time menu=time … axes=12`, against `(relaunch instead) compare state=none … axes=1`. A `scheme` comparison is cleared, but only because that option disappears.
  - `p17.log`: `adv bound + run locked=true xlims=(0.2, 0.4) ylims=(0.3, 0.6)`. The heat limits are applied to an advection x–t plot where y is time in [0, 1]. A relaunch gives `locked=false xlims=(0.0, 0.99) ylims=(0.0, 1.0)`.
- **Fix:** In `_reset_open_view!`, set the `compare_target` menu to `:none` and set `manager.camera_locked[] = false`. Or, if keeping them is intended, narrow the docstring and CHANGELOG ("axis menus and sliders").
- **Test:** Same as p16 and p17: assert compare `none` and an unlocked camera after a bind of another setup.

### 3. Title line breaks still change when a swept parameter changes the extent of a titled axis (low, CONFIRMED; residual of fb11adf finding 2)
- **Where:** `_title_values` (`src/PlottingUtils.jl`) takes the ends of an axis from `sim_data`, the drawn dataset, so the alternative texts change with the param sliders.
- **What:**
  - When the time horizon (or a domain length) is swept, `Time (T) = 10.000` is wider than `Time (T) = 1.000`.
  - Moving the `T` slider changes the line count, so the axis moves. On GLMakie, `resize_to_layout!` can also resize the window, and exported animations over `T` shift between frames.
  - The CHANGELOG states generally: "The breaks are chosen for the widest value of each part, so they stay while the sliders move."
- **Evidence:** `p13.log` at width 655:
  - `T=1 -> "T = 1.000 | Scheme = upwind | Time (T) = 0.000"`, axis origin `(629, 285)`.
  - `T=10 -> "T = 10.000 | Scheme = upwind\nTime (T) = 0.000"`, axis origin `(629, 270)`.
  - The alternatives of the time part are `["…0.000", "…1.000"]` vs `["…0.000", "…10.000"]`.
- **Fix:** Take the axis alternatives from something that doesn't depend on the param sliders. The dimension slider's range (`manager.widgets[dim].range[]`, already scaled to all active datasets) is the simplest. Otherwise use min/max over all datasets in `plot_data`.
- **Test:** Sweep `T => [1.0, 10.0]` in a `lines` style. Move `T` at several widths and assert that the line count (or the axis viewport) doesn't change.

### 4. A failed `launch_plotter(config)` leaves `launch_run` set; the next run in the old window reports the other configuration's summary (low, CONFIRMED)
- **Where:** `_prepare_for_config!` sets `manager.launch_run` right after its run. Anything that throws afterwards leaves it set, and `simulation_trigger` uses it on the next run.
  - `_resolve_plot_style(style)` throws inside `_prepare_for_config!` (via `_style_mode`) and again in `launch_plotter`. With a typo in `style`, the prepare run happens first and the error comes after it.
- **What:** The old window stays open. The next *Run Simulation* (or a mode switch, which forces a run) shows the counts and time of the failed launch's configuration.
- **Evidence:** `p11.log` case 5:
  - The heat window has 6 runs. `launch_plotter(adv(2 schemes); style = :heatmapp)` throws, leaving `launch_run = (RunSummary(2 tasks: 0 ran, 2 cached, 0 failed), …)`.
  - The Run click in the heat window then reports `Simulation finished in 0.0 s: 2 runs, 0 ran, 2 cached.`
- **Fix:**
  - Validate `style` (`_resolve_plot_style`) before the prepare run (this also avoids a wasted run).
  - Keep the summary in a local variable and assign `manager.launch_run` just before `force_simulation()` at the end of `launch_plotter`, or reset it in a `try`/`catch`.
- **Test:** `@test_throws ArgumentError launch_plotter(other; style = :bogus)`, then click Run and assert the status counts the bound configuration's runs, and `isnothing(manager.launch_run)`.

### 5. Editor sweep changes are not tracked by `bound_setup`; Reset Simulation then puts one parameter's slider value on another (low, CONFIRMED; the slot-keyed cache predates the commit)
- **Where:** `_after_raw_change!(:sweep, …)` and the Sweep editor change `active_config.varied` in place and remap the sliders. `bound_setup` keeps the setup of the last bind. `reset_sim_config!` compares the base config with that stale setup and finds them "the same".
- **What:**
  - After the editor adds a parameter that sorts first, the slot positions shift.
  - Reset Simulation then keeps the slot cache, so `scheme` takes the value `c` had in slot 1.
  - The commit message says "a sweep changed in place counts as another setup". That holds for `launch_plotter`, not for the editor in an open window.
- **Evidence:** `p12.log`:
  - After the edit and Run: `(:c, 2), (:scheme, "upwind")` (scheme's position 2 moved onto `c`).
  - With `c = 3`, `upwind` set and `slider_cache = Dict(:param_2 => 1.0, :param_1 => 3.0)`, after Reset and Run: `(:scheme, "lax_wendroff")`.
- **Fix:** Root cause: key the param entries of `slider_cache` by parameter name, not by slot. Alternatively, update `bound_setup` in `_after_raw_change!` / the sweep and solver editors, and reset the slider cache when the setup changes there.
- **Test:** p12 as a test: assert `scheme == "upwind"` after Reset Simulation.

### 6. The new `set_sim_config!` test doesn't catch the old behaviour (low, CONFIRMED)
- **Where:** `test/runtests.jl` 1066–1071 (bind `config` into a heat window, assert x–t and `cfl => 0.25, tag => "a"`).
- **What:**
  - On fb11adf these assertions pass.
  - Heat's `y` is invalid for 1D data, so the old code also falls back to `t`.
  - Heat's untouched `r = 0.1` in slot 1 maps to the nearest `cfl`, 0.25, which is also the default.
  - Only 1080 (the sweep changed in place) and the `_fit_title` calls fail on the old code.
- **Evidence:** `test_agent_old.log`: failures only at 1024, 1030–1032 (errors) and 1080.
- **Fix:** Bind in the direction of the original finding. After an advection x–t heatmap with `scheme = "lax_wendroff"`, `set_sim_config!(test_heat_2d()); force_simulation()`, then assert axes `x`/`y` and `r == 0.1`. The old code gives `(:x, :t)` and `r = 0.3` (fb11adf review, p01 E).

## Test coverage

- Good:
  - The animation-relaunch test (plots-1, GLMakie) and the sweep-changed-in-place test both fail on fb11adf.
  - The `_fit_title` unit tests cover the widest-value breaks and `" | "` in values.
- Gaps:
  - F1 (bind while animating), F2 (compare and camera on bind), F4 (failed launch), F5 (editor plus Reset).
  - F6: the bind test doesn't discriminate.
  - Title stability is only unit-tested on hand-built parts. Nothing moves a real slider (where `_title_values` supplies the alternatives) and checks the line count or viewport, so F3 would not be caught.
  - The `launch_run` behaviour has no test. The changed status test (`r"6 runs, \d ran, \d cached"`) accepts both `0 ran` and `6 ran`.
  - No tests for the new status branches: `:outdated`, `without output` → `:warn`, "no numerical runs (references only)". p18 shows they work.

## Minor issues

- **Between a bind of another setup and *Run*, the window is inconsistent.** It still draws the old plot, the slider row is gone, and the menus show values derived from the old data (`Y-Axis = Scheme`, which isn't plotted, and `Anim Target = Disabled`). The update buttons are locked until Run, so this is cosmetic. It shows after presets and Reset Simulation, which ask the user to press Run (`p11.log` case 1, `img/p11_bound_before_run.png`).
- **agents.md example:** after this commit, the documented snippet on a fresh save path prints `Simulation finished in 1.5 s: 6 runs, 6 ran, 0 cached.` (p07). The `0 ran, 6 cached` line shows only when results are already stored. Consider the fresh output, or a note that it depends on the cache.
- **Cost and cache are fine:** with 400 swept values, `_title_values` takes 0.024 ms and `_fit_title` 0.008 ms per call. `_TEXT_WIDTHS` grows with the distinct values (412 entries) and is capped at 10,000.
- **Handled correctly:** empty parts (`""`), NaN (`"A = NaN | B = 1"`), compare labels (left as they are), Axis3 and custom titles.
- **Run-button rebuild with `pending_domain`:** works. `launch_plotter()` followed by `set_sim_config!(config; snapshot = false)` sees the same setup and keeps the view (suite test passes).
- **CSV loads into an open window** apply their own axes and sliders after the reset (`p11.log` case 4). A structurally staged CSV goes through the same path after the rebuild.
- **`_run_status` wording** with `:outdated` reads well and warns (p18). With Core 0.4.4 it falls back to the time only.

## Verdict

5037fcd fixes the two medium problems of the last review as claimed for `launch_plotter(config)`: the animation leak, and titles that jumped for ordinary sweeps. It also fixes findings 4–7 and the minor issues. The full suite passes, and the Core 0.4.4 fallback works.

The extension to configurations bound into an open window is incomplete:
- **F1 (medium):** a running animation keeps driving a slider of the new setup. This is the same bug class as fb11adf finding 1. The fix is to stop the timer in `_reset_open_view!`.
- **F2:** the comparison and a locked camera survive a bind, although the docstring says the bind "does the same" as a launch.

The title claim needs F3 for sweeps that change an axis extent. I recommend fixing F1 (a few lines) before merging, along with F2 and F6 (either the fix or narrower wording, plus a discriminating test). F3–F5 can follow.

Counts: high 0, medium 1, low 5, plus 5 minor issues.
