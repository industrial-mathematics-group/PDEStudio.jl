## Findings

### 1. A failed `load_config_file!` of a recorded copy drops its origin, and the loaded configuration then runs and exports differently — low — CONFIRMED (regression)

- **Where:** `load_config_file!`. `delete!(manager.source_origins, file)` (`src/ConfigIO.jl:521`) runs before `Base.include` (`:523`).
- **What:**
  - Sequence: load an export whose `cfg.jl` was edited, so the copy `B/cfg.jl` is recorded and runs as `A/cfg.jl` with the unlisted `A/u.jl`. Then *Files → Load* the copy itself. That load fails, because `u.jl` isn't in B.
  - The active configuration is unchanged: its source is still `B/cfg.jl`. But the entry is gone, so:
    - the next Run runs `B/cfg.jl` as itself in B and fails (`u.jl` not found);
    - the next export silently records `B/cfg.jl` as its own origin, so reloading that export runs in the old bundle folder.
  - With 473d788 the failed load changed nothing: Run 2 was ok, and the export recorded A.
- **Evidence:** `probes/probe_origin_rule.local.out` case 1: "Run 2 … FAILS", "export now records: [B/cfg.jl]". `probe_origin_rule.oldsrc-local.out` case 1: "Run 2 ok", "[A/cfg.jl]".
- **Fix:** drop the entry only after the file ran and returned a `SimulationConfig` (after the `result isa SimulationConfig` check, or with the bind).
- **Test:** load an export with an edited `cfg.jl` that includes an unlisted helper. Then `@test_throws` on `load_config_file!(copy)` (helper missing in B), then `_origin_of(copy) == abspath(original)`, and Run succeeds.

### 2. The new status text pushes the failing file and its error out of the status line — low — CONFIRMED (regression)

### 3. After `load_config_file!` of one bundled copy, its sibling copies keep their origins: Run runs them in the original folder — low — CONFIRMED (residual of 473d788 finding 1 (b))

- **Where:** `load_config_file!` drops only the entry of the loaded file (`:521`); `_include_sources` uses every other entry.
- **What:**
  - Sequence:
    - `h.jl` (listed) and `cfg.jl` were edited after the export.
    - The user loads the export, makes B self-contained (copies `u.jl` and the data file `d.txt` into B), and loads `B/cfg.jl` as `.jl`.
    - Its sources are `[B/h.jl, B/cfg.jl]` (`joinpath(@__DIR__, "h.jl")` now points into B).
  - With the local Core, Run includes `B/h.jl` **as `A/h.jl`**, which reads `A/d.txt` ("dataA").
  - The registered Core, and Core's own `run_all_simulations`, run it in B and read "dataB".
  - The next export records mixed origins: `[A/h.jl, B/cfg.jl]`.
  - When `cfg.jl` also includes `h.jl` (`probe_run_semantics` case 8), Run runs `h.jl` twice: as A, then as B.
  - So the result of Run depends on the Core version, and on an export loaded earlier in the session that the loaded file no longer refers to.
- **Evidence:** `probes/probe_origin_rule.local.out` case 2 vs `.reg.out` case 2. `probes/probe_run_semantics.local.out` case 8: `["h v1 @A", "cfg v1 @B", "h v1 @B"]`.
- **Fix:** a successful `load_config_file!` replaces the configuration, so the origins of an earlier export load no longer apply: `empty!(manager.source_origins)` (after the run, see finding 1). Alternatively, drop the entries of all copies in the same `<name>_sources/` folder.
- **Test:** the case 2 sequence. After `load_config_file!(B/cfg.jl)`, `_origin_of(B/h.jl) === nothing`, and Run reads B's data file.

### 4. `include` in default values of a signature is not redirected — low — CONFIRMED (pre-existing, same in 473d788)

- **Where:** `_redirect_includes`, `kept` (`src/ConfigIO.jl:313`). For `:function`, and for `=` with a signature on the left, the whole signature is kept, including default values.
- **What:** with `h.jl` edited after the export, these run the **edited original** at the export load, and at Run with the local Core, while the note says "the exported version ran":
  - `fdef(x = include("h.jl")) = x; fdef()`
  - `fkw(; v = include("h.jl")) = v; fkw()`
  - `function f(; v = include("h.jl")) … end`
- **Evidence:** `probes/probe_name_heads.local.out`, the three "default" rows: ORIGINAL. `.reg.out`: ORIGINAL at the load. `.oldsrc-local.out`: the same.
- **Fix:** walk the signature instead of keeping it: keep the function name, the argument names and the types, and redirect the second argument of each `:kw`. Or document the limitation.
- **Test:** add `"fkw(; v = include(\"h.jl\")) = v; fkw()"` to `forms` in "Bundled sources: include forms".
