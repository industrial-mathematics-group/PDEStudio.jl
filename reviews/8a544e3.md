## Findings

### F1 — medium — CONFIRMED: `studio_set!` now runs or applies changes before an invalid slider name or value is noticed
- **Where:** `src/AgentAPI.jl`, `studio_set!`, in the slider phase (`if apply && !isempty(sliders) pressed = _apply_steps!(steps) …`).
- **What:** Names are only checked when their turn comes. Unknown names get `_SLIDER_RANK`, so they are checked last. That is after the first `_apply_steps!`, which may press *Run Simulation* (because of `:methods`), *Apply Layout* or *Update Plot*. So a typo or an out-of-range slider value now costs a full simulation run or a redraw, and then throws.
  - 0.6.0 also left partial state, but it was pending and not applied. Now it is applied.
  - The status line is not updated, so it describes the call before.
- **Evidence (p3):**
  - `studio_set!(:methods => [:upwind], :cfl => 7.0)` throws "outside its range", but the methods are already `[:upwind]`, `flags[:Simulation] == false` and the status says "Simulation finished … 8 runs".
  - `studio_set!(:x_axis => :t, :cfll => 0.5)` gives the new code `(Plot flag false, x = :t)` and status "Set x_axis = :x (update_plot)." (stale). The old code gives `(true, :t)`: pending, not pressed.
- **Fix:** check everything that can be checked before setting anything:
  - every name resolves to a control (`plot_style`, `methods`, a `_MENU_LABELS` or `_NUMBER_LABELS` key with a widget, `_slider_key(name)`, or one of `_unslid_parameters()`), using the existing error messages;
  - the type and range of slider values whose range won't change.
  
  Only then set and press.
- **Test:** `@test_throws ArgumentError studio_set!(:methods => [:upwind], :cfll => 1)`, then check that `config.defaults` and `flags[:Simulation]` are unchanged and no run happened. Same for `:x_axis => :t, :bogus => 1` with `flags[:Plot]`.

### F2 — low — CONFIRMED: calls that worked in 0.6.0 now throw when a slider belongs to the axis or comparison set in the same call
- **Where:** same ordering code.
- **What:** Sliders are always set last. If the same call puts that slider's dimension or parameter on an axis or into the comparison, the slider is disabled by then and the call throws. The axis or comparison change has already been applied at that point. This hits an agent that replays a state (all sliders plus the axes).
- **Evidence (p6b, old vs new):**
  - `studio_set!(:t => 1.0, :x_axis => :t)`: old sets `x = :t`; new throws "slider :t is disabled".
  - `studio_set!(:cfl => 1.0, :compare_target => :cfl)`: old sets the comparison; new throws "slider :cfl is disabled".
- **Fix:** in the slider phase, skip sliders that this same call disabled (they were enabled before the call, or their name is the new x/y/z axis, animation target or compare target), and mention them in the status line instead of throwing. Or set those sliders before the rest when they are enabled now.
- **Test:** both calls above succeed, with the axis or comparison applied.

### F3 — medium — CONFIRMED: the statistics hint is wrong in 2D/3D grid styles
- **Where:** `src/AgentAPI.jl`, `_statistics_hint`. Also `docs/src/agents.md` ("in the grid styles").
- **What:** The example only adds `:plot_style => :lines` in Lagrangian mode. In heatmap or contour, the suggested `studio_set!(:x_axis => :t, :u_axis => :l1error)` throws, because y is still `:x` and a statistic that keeps only t is not offered. It also leaves `x = :t, y = :x` set but not applied.
- **Evidence:** p2 "heatmap follow hint" gives `ArgumentError: u_axis has no option :l1error …` and then style `heatmap_flat`, axes `(x = :t, y = :x)`. p10 "contour hint" shows the same example.
- **Fix:** add `:plot_style => :lines` to the example whenever `PLOT_DIM_MAP[current style] > max(length(kept), 1)`. Say "1D grid styles (lines, scatter)" in the hint, the docstring and `agents.md`. Optionally mention that two swept parameters work in 2D styles (p10: x = cfl, y = tag offers all the statistics).
- **Test:** in a heatmap, the `:u_axis` label contains `:plot_style => :lines`, and evaluating the suggested call gives `axes.u === :l1error`.

### F4 — low — CONFIRMED: values in [1e-3, 1e-2) still get one significant digit
- **Where:** `src/PlottingUtils.jl`, `_fmt_value`.
- **What:** The switch to `%.3g` happens only below 1e-3. So `0.0015` and `0.002` both show as "0.002", and `0.0012` shows as "0.001". A sweep like τ ∈ {1e-3, 1.5e-3, 2e-3} shows duplicate slider, title and description texts, and `_title_values` deduplicates them. This is the same class of bug as the reported "0.000".
- **Evidence:** p4 gives `fmt 0.0015 → "0.002"`, `0.002 → "0.002"`, `0.0012 → "0.001"`.
- **Fix:** use `%.3g` (or `round(v, sigdigits = 3)`) below 0.1, or for every value outside [0.1, 1e5).
- **Test:** `_fmt_value(0.0015) != _fmt_value(0.002)`.

### F5 — low — CONFIRMED: multi-line titles on Axis3 are cut off and overlap
- **Where:** `src/PlottingUtils.jl`, `_set_title!` / `_fit_label`, applied to Axis3 compare titles.
- **What:** Axis3 has a fixed protrusion (`ax.protrusions[] == 30`). It doesn't grow for a 2–4 line title. So in compare layouts of 3D styles:
  - the first title lines run out of the top of the window or snapshot;
  - titles in the second row overlap the axes of the first row.
  
  0.6.0 overflowed sideways instead, so for Axis3 the overlap is moved, not removed. 2D `Axis` is fine.
- **Evidence:** `p11_axis3_window.png` (top title shows only "scheme_without_ / limiter"; "ÄÖÜ_αβγ_Lax_ / Friedrichs_ / …" sits over row 1), `p9_new_axis3_compare.png`, `p5_axis3.png`.
- **Fix:** for `Axis3`, keep one line shortened with "…" (`_shorten_to(label, fits)`), or raise the top protrusion by the extra line heights.
- **Test:** Axis3 compare with a long method name at `plot_width = 250`: the title has no `"\n"` (or the protrusion is raised).

### F6 — low — CONFIRMED (documentation): error vs a parameter compares runs at different times
- **Where:** `docs/src/agents.md` and the `studio_set!` docstring ("the error over a swept parameter, at t = 1").
- **What:** This behaviour is not new, but the commit now recommends it. Each point uses its own run's nearest stored time. With CFL-tied time steps those times differ, while the title shows only one of them. The same applies to the final time.
- **Evidence (p7, at t = 1):** cfl 0.25, 0.5 and 1.0 use t = 0.9817, cfl 0.75 uses t = 1.0308. The title says "Time (T) = 0.982". At t = 2, the runs end at 2.0126 and 2.0617.
- **Fix:** say this in the docs (nearest stored time per run; for convergence plots use a common output time or a final-time statistic). Optionally have `studio_data` report the times used.
- **Test:** none needed (documentation).

### F7 — low — CONFIRMED: custom titles with a newline are not reported as one line
- **Where:** `_set_title!` (`manager.title_texts[...] = text` with `text = custom`) and `_plot_state`.
- **What:** The CHANGELOG says "`studio_state` reports titles as one line of text". A custom title with `"\n"` is now reported with the newline. 0.6.0 replaced it with " | ".
- **Evidence:** p5 "custom api" gives `"Line one\nLine two"`.
- **Fix:** store `replace(text, "\n" => " | ")`.
- **Test:** `studio_option!(:labels, :title, "a\nb")` gives `studio_state().plots[1].title == "a | b"`.

## Minor issues

- The `studio_set!` docstring says "with `apply = false` it stays disabled". In fact the call throws `ArgumentError` after the other changes have been staged (p3).
- `_statistics_hint` describes the whole list using the kept dimensions of the alphabetically first statistic. The list says "over :t or a swept parameter" even though `spacetime_relative_mass` only works over a parameter. Without any sweep it still says "or a swept parameter", and lists statistics that can't be plotted at all. The list is cut at 80 characters, so the scalar statistics are hidden.
- The note on the `:x_axis` label ("an entry :stat|dim …") is also added in Lagrangian mode, where there are no such entries. The `describe_studio` sample in `agents.md` still shows "— X-Axis".
- Claim 2 judgement: for the 1D grid styles and the particle styles the hints solve what the agent reported. The `stat|dim` x entry is still a trap in the GUI: by default it plots Solution against the statistic (`p2_statdim.png`). It is now only documented for agents.
- Older issues, still there:
  - Titles of statistic plots list dimensions the statistic doesn't keep ("Position (X) = 0.000", even for scalar statistics).
  - The axis label for a `stat|dim` entry is "L1Error|T", while the menu says "L1Error (Time)".
  - `frontend_key(:α_max)` gives "Α Max" (capital Greek Alpha).
- `frontend_key` reads every `__` as a tuple entry: `:my__param` becomes "My[param]", `:a__b__1` becomes "A[b][1]". This is acceptable under Core's naming convention.
- Opening the labels editor page writes the default labels into `manager.labels` (`UILogic.jl:1244`), and those are saved to visual CSVs (`ConfigIO.jl:56`). Presets saved with 0.6.0 therefore keep "Grid Ns  1" and "Pde Tau". This is older behaviour; a CHANGELOG note may be worth it.
- At very narrow widths, `_fit_label` puts every word on its own shortened line ("u…\nfi…\n…", up to 8 lines; `p5_methods_50.png`). Capping at 2 lines and then shortening would look better.
- The CHANGELOG header still says released versions are described in the GitHub releases, but the file now has a "## 0.6.0" section. Otherwise the CHANGELOG entries match the behaviour (apart from F7 and F3's "grid styles").
- Values in claim 4 are display-only: `_fmt_value` is not used in `ConfigIO` or the exports, so stored values are unchanged. Negative, Float32, huge, Int, NaN and Inf all format sensibly. `set_label!` still wins.

## Verdict

The five reported problems are fixed in the cases the user's agent hit, and nothing regressed in the existing suite (full suite green). Two new issues should be fixed before merging:

- the hint example that fails in 2D styles (F3);
- the slider-last ordering now applying changes, including simulation runs, before an invalid name or value throws (F1), together with the related regression for calls that worked in 0.6.0 (F2).

The rest are small. Merge after F1 and F3 are fixed; F2, F4 and F5 are recommended.

Counts: 0 high, 2 medium (F1, F3), 5 low (F2, F4, F5, F6, F7); all CONFIRMED. Plus 9 minor issues.
