## Findings

### F-A — medium — CONFIRMED: titles of compared methods with a common prefix become identical (Axis3 one-line shortening, 2D two-line cap)
- **Where:** `src/PlottingUtils.jl`, `_set_title!` (the `ax isa Axis3` branch: `_shorten_to(text, …)`) and `_fit_label` (`length(lines) > 2 && (lines = [lines[1], join(lines[2:end])])`).
- **What:** Both new rules cut the end of the label. Method names usually differ at the end. So in a methods comparison, the subplots get the same title, and nothing else in the plot tells them apart (no legend; see `q5_2d_150.png`, `q5_3d_300.png`).
  - 0.6.0 showed the full names (overflowing sideways).
  - 8a544e3 showed the full names on several lines.
  - So relative to both, this loses information. For Axis3 it already happens at a common width of 400 px.
- **Evidence (`q5`):** methods `upwind_first_order_scheme_without_limiter` and `upwind_first_order_scheme_with_limiter`.

  | Plot | Width | 8c49b66 | 8a544e3 |
  |:--|:--|:--|:--|
  | 3D | 400 | `"upwind_first_order_scheme_…"` twice | `"upwind_first_order_scheme_\nwithout_limiter"` / `"…\nwith_limiter"` |
  | 3D | 300 | `"upwind_first_order_s…"` twice | distinct |
  | 2D | 200 | `"upwind_first_\norder_schem…"` twice | `"upwind_first_\norder_scheme_\nwithout_limiter"` / `"…\nwith_limiter"` |
  | 2D | 150 | identical | distinct |

  At 3D 500 px the two titles are still distinct (`"…without_…"` vs `"…with_limi…"`). `studio_state` reports the full names, so an agent can't see the collision.
- **Fix:** keep the part that differs:
  - shorten in the middle (`"upwind_first…without_limiter"`); or
  - when the shortened titles of one comparison collide, drop their common prefix (`"…without_limiter"` / `"…with_limiter"`).
  
  For Axis3, a second line plus that much more top protrusion would also work.
- **Test:** methods comparison of the two names above at `plot_width = 300`, both in `:heatmap_surface` and `:lines` at 150 px: `allunique(drawn titles)`.

### F-B — low — CONFIRMED: the default title of a 3D plot loses its last parts (usually the time) at moderate widths
- **Where:** same Axis3 branch of `_set_title!`. It shortens the whole joined text `join(parts, " | ")` instead of using `_fit_title`'s part-wise layout.
- **What:** The cut lands in the last part, which is typically `Time (T) = …`, the value that changes in an animation. The plot-area snapshot (`studio_snapshot`, default area) and animation exports only contain the plots, not the sliders. So in those images the time is gone.
- **Evidence (`q10`):** heatmap_surface with x = x, y = tag:
  - 400 px: `"Cfl = 0.250 | Time (T) = 0.000"`
  - 300 px: `"Cfl = 0.250 | Time (T) …"`
  - 250 px: `"Cfl = 0.250 | Time …"` (`q10_axis3_single250.png`)
- **Fix:** for Axis3, drop whole parts from the front, or shorten the labels before the values (`"T = 0.000"`). Or allow the two-line `_fit_title` with a raised protrusion.
- **Test:** heatmap_surface at width 300: the drawn title contains `"= 0.000"` for the time part.

### F-C — low — CONFIRMED: F4's rounding duplicates moved one decade up; one sweep now mixes precisions
- **Where:** `src/PlottingUtils.jl`, `_fmt_value` (`1e-2 <= abs(v) < 1e5 ? "%.3f"`).
- **What:** Values in [0.01, 0.1) still get only 2 significant digits. The same `0.0015`/`0.002` problem now shows up as `0.0125`/`0.013`. One sweep can show some values exactly and round others.
- **Evidence (`q4`):**
  - τ ∈ {0.005, 0.0075, 0.01, 0.0125, 0.015} shows `0.005, 0.0075, 0.010, 0.013, 0.015`.
  - `0.0125`, `0.013` and `0.0135` all show `0.013`.
  - A time slider 0:0.0005:0.05 has 20 values with 20 distinct labels below 0.01, but 81 values with only 41 distinct labels from 0.01 up (`0.010, 0.011, 0.011, 0.011, 0.012`).
- **Fix:** use `%.3g` below 0.1, as the previous review suggested.
- **Test:** `_fmt_value(0.0125) != _fmt_value(0.013)`.

### F-D — low — CONFIRMED: F1 is only half fixed; slider values are still checked after pressing
- **Where:** `studio_set!`. Only `_check_control_name` runs up front. Slider type, range and enabled state are checked in `_set_slider_control!`, after `_apply_steps!`.
- **What:** Typos are now caught before anything happens. But an out-of-range, non-numeric or disabled slider value still costs a simulation run, Apply Layout or Update Plot before it throws. The status line then still describes the previous call. The commit message only claims names, but F1 also asked for the values.
- **Evidence (`q1`):**
  - `studio_set!(:methods => [:upwind], :cfl => 7.0)` throws "outside its range". By then active = `[:upwind]`, `flags[:Simulation] == false`, and the status says "Simulation finished … 8 runs".
  - `studio_set!(:x_axis => :t, :cfl => 7.0)` leaves x = `:t` applied.
  - `studio_set!(:plot_width => 450, :x => 0.5)` (x is the plot axis) applies the width, then throws "slider :x is disabled".
- **Fix:** before setting anything, check the type of every slider value, plus the range of sliders that are enabled now and that this call doesn't free (not the former compare target or axis). Sliders whose range can change stay checked at the end.
- **Test:** `@test_throws ArgumentError studio_set!(:methods => [:upwind], :cfl => 7.0)` leaves `config.defaults` unchanged.

## Minor issues

- **Skip note gives the wrong reason** (`q6`). `studio_set!(:u_axis => :l1error, :x => 0.5)` with x = t skips `:x` "(now a plot axis or the compare target)". The real reason is that the statistic doesn't keep x. Something like "(disabled by this call)" would be accurate.
- **A skipped slider's value is never checked.** `studio_set!(:t => "abc", :x_axis => :t)` succeeds with "not set: :t".
- **Punctuation on the reported-status path:** "Simulation finished in 0.0 s: 8 runs, 0 ran, 8 cached.; not set: :cfl (…)" has ".;" and no final period.
- **Mixed-kept-dims hint without a sweep** (`q3` "mixed, heatmap, no sweep") says "over the dimensions each keeps or a swept parameter". The `allequal` branch uses `over()`, which does check `params`; the mixed branch doesn't.
- **`_check_control_name` accepts `:methods`** even when `studio_controls` doesn't list it (no config). The later error is clear and only the staged style is pending, so this is harmless.
- **Truncation is invisible to agents.** `studio_state` reports the full text for shortened Axis3 titles, so an agent can't tell a title was cut (see F-A).
- **Test gaps:**
  - nothing tests distinct titles under shortening (F-A);
  - no slider-value error after a press (F-D);
  - no `_fmt_value` value in [0.01, 0.1);
  - the Axis3 test only checks "no newline and one ends with …", which passes even when both titles are identical.

## Verdict

8c49b66 fixes F2, F3, F6 and F7 fully, and fixes the main part of F1 (names). The statistics hint now works when followed in every style and data kind I tried. The full suite is green, and the new tests catch the 8a544e3 code.

The F5 fix trades the overlap for lost information. Compared methods with a common prefix get identical titles at ordinary widths (F-A, medium), and narrow 3D titles drop the time (F-B). I recommend fixing F-A before merging: shorten in the middle, or drop the common prefix. F-C (`%.3g` below 0.1) and F-D (pre-check slider values) are small follow-ups.

Counts: 0 high, 1 medium (F-A), 3 low (F-B, F-C, F-D); all CONFIRMED. Plus 6 minor issues. Earlier items: 5 fixed (F2, F3, F5 with side effect, F6, F7) and 2 partly fixed (F1, F4).
