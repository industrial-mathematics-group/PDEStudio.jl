API Reference

Here is the complete public API for PDEStudio.jl.

PDEStudio.describe_studio — Function
describe_studio(io::IO = stdout)

Prints what the studio shows, for a person or an agent reading it: the status line, the configuration, the plot style and the variables on the axes, every subplot (title, labels, shown limits, 3D camera, range of the plotted values per method) and every control with its value and choices (the names studio_set! and studio_press! take). studio_state returns the same as data.

source
PDEStudio.force_simulation — Method
force_simulation()

Manually pushes an asynchronous trigger to the :Simulation observable, forcing the backend to re-evaluate the active SimulationConfig.

source
PDEStudio.launch_plotter — Function
launch_plotter(config = nothing; style = nothing) -> Figure

Builds the studio window and returns its Figure (show it with display, or use @launch, which does).

  • style: the plot style to start with, a group (:lines, :scatter, :contour, :heatmap, :volume, :particles: its first style) or a style (e.g. :heatmap_surface, :contour_3d, :particles_2d). The axes follow from the data: a 2D style shows x and y, or x and t for 1D data. The particle styles draw the data as particles (Lagrangian), all others on a grid (Eulerian); data of the other kind is converted.
  • config: a SimulationConfig to bind and run. It is run first (the results are cached), so the window starts with the right setup: without a style, particle data opens in a particle style; axes the window doesn't know yet (such as a time axis :iteration) are added (see set_allowed_dims!). A configuration with other swept parameters or solvers than the bound one starts with its default view (plotted axes, sliders, animation target, comparison, camera); launching the same setup again keeps the plotted axes, slider positions and comparison of the last window (a locked camera is unlocked). set_sim_config! does the same in an open window.
fig = launch_plotter(; style = :heatmap)              # empty window, heatmaps once data arrives
fig = launch_plotter(test_heat_2d(); style = :heatmap)
display(fig)

PDEStudio.reset_manager! — Method
reset_manager!()

Returns the PlotManager to its pristine state: detaches every listener, drops the UI dictionaries, widgets, caches, labels and the bound configuration, rebuilds the trigger tree and reloads the default styles and the presets found on disk. The mode, the allowed dimensions, the number of parameter sliders and the window handle are kept (see reset_plotter! for the window).

source
PDEStudio.reset_plotter! — Method
reset_plotter!()

Safely resets the Makie rendering engine. It systematically closes the active display screen, clears the Figure cache, and explicitly detaches all reactive ObserverFunction listeners to prevent memory leaks and ghost updates during hot reloads.

source
PDEStudio.reset_sim_config! — Method
reset_sim_config!()

Restores the simulation configuration that was last bound with set_sim_config! (or loaded from a project CSV), discarding simulation presets and editor changes applied since. Flags the simulation for a re-run.

source
PDEStudio.save_plot_preset — Method
save_plot_preset(name; description = "")

Saves the current look of the studio—layout, axes and slider positions, camera, labels, exploration options and all UI styles—as the visual preset <save path>/Presets/<name>.csv. Simulation parameters are not included, so the preset can be applied to any simulation with set_plot_preset!. Returns true on success.

source
PDEStudio.save_sim_preset — Method
save_sim_preset(name; description = "")

Saves the simulation category of the bound configuration—shared parameters, the active methods and their parameters, the parameter sweep and the reference / post-processing functions—as the simulation preset <save path>/Presets/Simulation/<name>.csv. Nothing visual is stored. Returns true on success.

Apply it later with set_sim_preset!.

source
PDEStudio.set_allowed_dims! — Method
set_allowed_dims!(dims::Tuple{Vararg{Symbol}})

Defines the foundational mathematical dimensions the studio expects to render (e.g., (:x, :y, :t)). Adapts the base UI slider banks accordingly and completely resets the plotter to apply the new physical boundaries.

source
PDEStudio.set_max_params! — Method
set_max_params!(n::Int)

Globally configures the maximum number of custom VariedDict sweep parameters the UI will allocate sliders for. Triggers a complete UI reset.

source
PDEStudio.set_mode! — Method
set_mode!(mode::Symbol)

The data behind the plot styles: :eulerian (grids, every grid style) or :lagrangian (particles, the particle styles particles_*). Usually there is no need to call it: choosing a plot style sets it (the style page, presets, CSV files, launch_plotter(; style) / @launch). Data of the other kind is converted (PDEStudioCore's convert_to_eulerian / convert_to_lagrangian), so every style shows every dataset; statistics over time or swept parameters are plotted with the grid styles.

The switch is live: the open window, the bound configuration, the look and the editors are kept; the data is reloaded (the results are cached) and a plot style of the other kind is replaced by the default of the new one (lines_1d / particles_1d).

source
PDEStudio.set_plot_preset! — Method
set_plot_preset!(name)

The public entry point for loading visual themes. It checks if the requested name exists as a hardcoded apply_plot_preset! dispatch. If not, it loads the custom <save path>/Presets/<name>.csv template. Only the visual part of a file is applied (scene, UI styles, labels, exploration); simulation parameters and bundled source files are ignored, so a visual preset never changes the physics.

source
PDEStudio.set_plot_preset! — Method
set_plot_preset!()

A global reset routine. It purges the actively mutated manager.ui dictionary, forces a hard reload of all base layout options and exploration variables, and triggers a :Layout rebuild to return the studio to a pristine default state.

source
PDEStudio.set_resolution! — Method
set_resolution!(dim::Symbol, val::Int; is_ref::Bool=false)

Dynamically sets the internal interpolation and rendering resolution for a specific spatial or temporal dimension. Can target either the numerical baseline grid or the highly-resolved analytical reference grid. For a time axis it is the most snapshots shown: data is not interpolated in time, but shows its stored snapshots (all of them up to val, otherwise val of them, evenly spread); a reference uses the times of the data it is drawn with (at most val of them with is_ref = true).

source
PDEStudio.set_sim_config! — Method
set_sim_config!(file::AbstractString)

Loads a configuration from a file: a CSV (exports, presets; applied with load_and_apply_csv!) or a Julia file whose last expression is the SimulationConfig (or a function returning it; run with load_config_file!, which executes its code). file is a path or a file name searched for with find_config_csv (a name without extension means a CSV). Returns true if the file changes structural UI limits (the change is staged until Run Simulation), false otherwise, and nothing if no file was found.

source
PDEStudio.set_sim_config! — Method
set_sim_config!(config::SimulationConfig; snapshot = true)

The primary injection point for connecting a PDEStudioCore physics configuration to the PDEStudio interactive UI.

This function unpacks the SimulationConfig, maps the dynamic parameter sweeps to the available UI sliders, builds the backend-to-frontend symbolic translation dictionaries, and flags the simulation for a (re)run. With snapshot = true (the default) a copy of config is kept as the baseline that Reset Simulation (see reset_sim_config!) returns to.

source
PDEStudio.set_sim_preset! — Method
set_sim_preset!(name; mode = nothing)

Applies the simulation preset <save path>/Presets/Simulation/<name>.csv to the studio and flags the simulation for a re-run. Two modes exist:

  • :replace: the preset defines the whole simulation (shared parameters, methods, active methods, sweep, functions). Presets saved with save_sim_preset (or Files → Simulation → Save) use this mode.
  • :patch: only the entries in the file change; everything else of the bound configuration is kept. This is the default for hand-written files without a Metadata, Preset, mode row, e.g. a two-line "high resolution" preset.

mode overrides the mode stored in the file. The source files of the bound configuration are always kept. Returns the new SimulationConfig (or nothing if the preset was not found).

source
PDEStudio.studio_controls — Method
studio_controls() -> Vector{NamedTuple}

The controls of the studio, as studio_set! and studio_press! take them: (name, kind, value, choices, label, applies), where kind is :slider (choices: the slider values), :menu, :number (choices: (lo, hi)), :style (the plot styles the data allows), :methods (the methods of the configuration; the value is the active ones, in drawing order) or :button, and applies the button that applies a change (studio_set! presses it for you). Sliders are named by their parameter or dimension (e.g. :N, :t).

source
PDEStudio.studio_data — Function
studio_data(plot = 1) -> NamedTuple

The numbers subplot plot draws, per method: (plot, variables, methods) where variables names what the axes show (x, y, z, the dependent field u and its component) and methods[m] holds the drawn coordinates and values of method m (x, y, z, u for grid data, points and u for particles), as plotted (after the display resolution). Use it to compute with what is shown instead of reading it from an image.

source
PDEStudio.studio_headless! — Method
studio_headless!()

Makes CairoMakie the active Makie backend, so the studio runs without any display (no window, no X server, no browser): launch_plotter then builds the studio in memory, and an agent or script works with it through the studio_* functions (see describe_studio) and looks at it with studio_snapshot. Not needed for snapshots of a visible window (they are always rendered by CairoMakie).

using PDEStudio
studio_headless!()
launch_plotter(test_heat_2d(); style = :heatmap)
describe_studio()
studio_snapshot("heat.png")

PDEStudio.studio_option! — Method
studio_option!(scope, key, value) -> String

Changes an option of the look, as the UI tab does (see studio_options for the scopes and keys), checked like the tab's input, and redraws: e.g. studio_option!(:plot_style, :color_map, :plasma), studio_option!(:y_axis_1d, :log_scale, true) or studio_option!(:labels, :title, "Advection"). Returns the status line.

source
PDEStudio.studio_options — Method
studio_options([scope]) -> Dict

The options of the look (the UI tab), by scope: :plot_style (colours, colormap, line width, levels, …), :labels (title and axis labels), :axis_general (font sizes), the axis scopes (:x_axis_1d, :y_axis_1d for 1D plots, :x_axis_nd, :y_axis_nd, :z_axis_3d for 2D and 3D plots: log scale, limits, ticks, …), :hud and :outliers_extrema. Returns a copy; change them with studio_option!.

source
PDEStudio.studio_pan! — Function
studio_pan!(dx, dy = 0, dz = 0; plot = :all)

Moves the shown part of the plots by fractions of the current view: studio_pan!(0.25) shows what lies a quarter of the view width to the right, studio_pan!(0, -0.5) half a view height further down (dz for 3D plots). Log-scaled axes move on the log scale. The view stays when the data updates (see studio_view!). Returns the new limits per subplot.

source
PDEStudio.studio_press! — Method
studio_press!(name) -> String

Presses a button of the studio: :run (Run Simulation), :apply_layout, :update_plot or :lock_camera (toggles the camera lock; a view set by the studio_* camera functions is then the person's own and stays). The work is done when it returns; it returns the status line. Like studio_set!, a press that changes the plotted variables, the style or the comparison releases a view set before (see studio_view!).

source
PDEStudio.studio_reset_view! — Method
studio_reset_view!()

Returns all plots to the automatic view: the limits follow the data again (also after the data changes), 3D plots get the default camera angles, and the camera lock is released.

source
PDEStudio.studio_rotate! — Function
studio_rotate!(dazimuth, delevation = 0; plot = :all)

Turns the camera of the 3D plots by dazimuth degrees around the vertical axis and delevation degrees up (the elevation stays within ±90°). 2D plots don't rotate; with plot = :all they are skipped. The view stays when the data updates (see studio_view!). Returns the new limits and angles per subplot.

PDEStudio.studio_set! — Method
studio_set!(name => value, ...; apply = true) -> NamedTuple

Sets controls of the studio, as a person would in the window, and applies them: sliders (by parameter or dimension name, e.g. :N => 128 or :t => 1.5; the nearest slider value is taken, non-numeric sweeps by their value), menus (:x_axis => :t, :u_axis => :l2error, :compare_target => :methods, … by value or label), the plot style (:plot_style => :heatmap_surface, also groups such as :contour), the numbers of the layout (:plot_width => 600) and the active methods (:methods => [:upwind, :exact]). See studio_controls for the names, values and choices. With apply = true the button a change needs is pressed afterwards (Update Plot, Apply Layout or Run Simulation, once for all changes, also if a change made before is still pending). The changes of one call are made in the order the controls depend on each other, whatever order they are given in: the plot style, the methods, the layout and comparison, the axes (x, y, z, then the dependent field, whose statistics depend on the axes), and the sliders after the rest is applied: a slider that a change frees (e.g. the former compare target) can be set in the same call (with apply = false it is still disabled then, and the call throws), and a slider the same call puts on a plot axis or into the comparison is left as it is (the status line names it). Every name is checked before anything is set; an invalid name or value throws an ArgumentError that lists the valid ones. Returns (values, status): the value each control has now and the status line.

Statistics are dependent fields (:u_axis) over the dimensions they keep or over swept parameters, in a 1D grid style (particle data is converted): an error over time is studio_set!(:plot_style => :lines, :x_axis => :t, :u_axis => :l1error), over a swept parameter studio_set!(:x_axis => :N, :u_axis => :l1error). The latter takes each run at its stored time nearest to the :t slider (runs with other time steps can differ there; for convergence studies use a common output time or a statistic of the final state).

studio_set!(:plot_style => :heatmap, :x_axis => :x, :y_axis => :t)
studio_set!(:N => 128)
studio_set!(:compare_target => :methods, :compare_columns => 3)
studio_set!(:compare_target => :none, :cfl => 0.5)   # (the slider the comparison held)

PDEStudio.studio_snapshot — Function
studio_snapshot(path = nothing; plot = :all, area = :plots, px_per_unit = 1) -> String

Renders what the studio shows to a PNG file and returns its path (by default a new file in <save path>/snapshots/), without changing the window. area = :plots gives the plot grid (with colorbars and legends), :window the whole studio with the control panel, as a person sees it; plot = i gives subplot i with its axis labels, title and its own colorbar or legend. px_per_unit scales the image (2 for twice the resolution).

A GLMakie window renders the snapshot itself; otherwise (without a display, see studio_headless!, or in a browser) CairoMakie renders it. CairoMakie can't draw volumes: a snapshot of a volume plot then shows the empty axes, and the status line warns about it.

studio_snapshot()                          # the plots, e.g. "…/snapshots/studio_2026-11-09_14-03-12-123_1.png"
studio_snapshot("overview.png"; area = :window)
studio_snapshot("detail.png"; plot = 2, px_per_unit = 2)

PDEStudio.studio_state — Method
studio_state() -> NamedTuple

What the studio shows, as data (the same as describe_studio prints): the status line, the bound configuration (solver, methods, swept parameters), the plot style and the variables on the axes, the comparison, the sliders, and per subplot its title, axis labels, shown limits (and 3D camera angles in degrees) and the range of the plotted values per method. Use it to check the result of an action; studio_data gives the plotted numbers themselves.

source
PDEStudio.studio_view! — Method
studio_view!(; plot = :all, xlims = nothing, ylims = nothing, zlims = nothing, azimuth = nothing, elevation = nothing)

Sets what the plots show: the limits of their axes ((lo, hi) in data coordinates) and, for 3D plots, the camera angles in degrees (azimuth around the vertical axis, elevation above the horizontal plane). Arguments left at nothing keep their current value; plot selects one subplot (1, 2, … as in studio_state) or :all. The view stays while sliders move and the data updates (the camera is locked, as with Lock Camera), until the plotted variables, the plot style or the comparison change, or studio_reset_view! returns to the automatic view. Returns the new limits per subplot.

studio_view!(xlims = (0, 1), ylims = (-0.1, 1.1))        # a 2D plot
studio_view!(azimuth = 30, elevation = 20)                 # a 3D plot from another side
studio_view!(plot = 2, zlims = (0, 0.5))                   # the second subplot only
source
PDEStudio.studio_zoom! — Function
studio_zoom!(factor = 2; plot = :all, center = nothing, dims = :all)

Zooms the plots in (factor > 1) or out (factor < 1): the shown range of each axis shrinks by factor around center (a tuple of data coordinates, one per axis direction) or around the middle of the current view. dims restricts the zoom to some axis directions (:x, (:x, :y), …; log-scaled axes zoom on the log scale). Zooming a 3D plot narrows its limits, so what lies outside is cut off, as when zooming with the mouse. The view stays when the data updates (see studio_view!). Returns the new limits per subplot.

studio_zoom!(4)                              # 4× closer, around the middle
studio_zoom!(2; center = (1.5, 0.3))        # around a point of interest
studio_zoom!(0.5; dims = :y)                 # show twice the y range

PDEStudio.@launch — Macro
@launch [style] [config]

Opens the studio and shows it, optionally with a plot style and a configuration to run:

@launch                              # the empty studio
@launch heatmap                      # heatmaps once data arrives
@launch test_advection_1d()          # run a configuration and show it
@launch heatmap test_heat_2d()       # both
@launch contour_3d my_config         # a specific style (see `launch_plotter`) and a variable
@launch particles test_particles_2d()   # the particles at their positions

The same as display(launch_plotter(config; style)) (see launch_plotter); in a browser (WGLMakie) the returned figure is shown by whoever displays it (REPL, notebook, Bonito app) instead. Returns the Figure.
